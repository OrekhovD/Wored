## Открыто

### Q-1. Серверный отказ просроченного прогноза
**Provenance: восстановлено из разговора, определение требует подтверждения.**
Формулировка, которую я помню: прогноз с истёкшим горизонтом не должен
сохраняться и не должен отдаваться в дашборд как живой — проверка на сервере, а
не только в UI. Перед правкой показать план и список файлов: это активный path
`webui/`, и я не имею права переделывать его по половинке ярлыка.

### Q-2. `ProviderTests` — реальный разрыв контракта
**Provenance: подтверждено прогоном.**
`tests/stabilization/test_contracts.py::ProviderTests::test_native_adapter_rejects_thinking_only_and_truncated_response` — ожидается `ValueError` на thinking-only и обрезанный ответ, он не бросается. Единственный из пяти отказов гейта, который нельзя списать на сборку образа.

### Q-3. Насыщенность `accuracy_score` делает калибровку односторонней
**Provenance: подтверждено данными прод-BД, 2026-09-22.**

| роль | оценённых точек | средняя accuracy |
|---|---|---|
| neutral | 91 | 19.5 |
| arbiter | 52 | 99.9 |
| bear | 38 | 99.7 |
| bull | 38 | 99.8 |

Порог дампинга — `< 50`, значит из всей накопленной истории калибровка коснулась
бы одной роли `neutral`, а три роли с ~99.8 не будут откалиброваны никогда.
Значения под 100 выглядят как метрика, измеряющая не угадывание направления.
Разбирать нужно в `collector/predictions/evaluator.py` — чужой активный path,
поэтому регистрирую, а не правлю.

### Q-4. Гейт не замечает устаревший образ
**Provenance: подтверждено дважды.**
`docker compose -f docker-compose.qa.yml run --rm checks` без `--build` тихо
прогоняет код до правок (зафиксировано: `grep -c` по новому классу внутри
контейнера = `0`, сбор 22 теста вместо 33). Костыль в документации есть;
постоянное решение — цель `make qa` с `--build`, либо проверка в самом образе.
Требует изменения `Makefile` — показать diff перед применением.

### Q-5. Пункты «C» и «D» прежней очереди
**Provenance: определения утрачены вместе с реестром, восстановить нечем.**
В репозитории под меткой `B3`/`C`/`D` находятся только посторонние старые
документы из `TASOCHKI/`. Нужен диктант формулировок, иначе пункты не существуют.

## Наблюдение, не задача

Фильтр `_fetch_role_accuracy` требует `metrics_version = 2`; в прод-БД 219
оценённых точек имеют версию `1`, версий `2` — ноль. Записывает `2`
`collector/predictions/evaluator.py:171`, то есть калибровка начнёт получать
данные по мере новых оценок. Правку это не требует, но объясняет, почему после
`c2fe3bf` запрос в живом контейнере ещё возвращает `None` по всем ролям.
