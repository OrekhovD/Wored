## 1. Контекст и исходное состояние

WORED — local-first система AI-аналитики крипторынка HTX. Runtime-стек (Docker Compose):

| Сервис | Роль |
|---|---|
| `postgres` | alerts, ai_journal, forecast-таблицы, sim-позиции |
| `redis` | hot ticker cache, pub/sub |
| `collector` | HTX WebSocket ingestion, индикаторы, scheduler, оценка прогнозов |
| `chatbot` / `chatbot_wored` | Telegram-боты (aiogram 3), AI routing |
| `webui` | FastAPI dashboard + TradingView Lightweight Charts |

**Исходное состояние на момент начала работ (2026-09-06):**

1. Docker Desktop не запущен — весь стек лежал.
2. `collector` в crash-loop: `NameError: name 'regenerate_hourly_correction' is not defined`.
3. Ollama Cloud API-ключ был **read-only** — `/v1/models` отдавал 200, но inference
   (`/v1/chat/completions`, `/api/chat`) возвращал 401. Все 90 forecast-запросов в БД
   были в статусе `failed` (429/410).
4. Прогнозы не оценивались: 72 forecast points с `target_time` в прошлом, но
   `actual_price = NULL`.
5. Worker-цепочка chatbot содержала 13 моделей, из которых 11 были мёртвыми
   (DashScope 402 Arrearage, OpenRouter 402, DeepSeek 402, NVIDIA NIM 410 Gone).

## 3. Ключевые архитектурные решения (требуют внимания ревьюера)

### 3.1 Двойной API Ollama Cloud — источник путаницы

**Проблема:** reasoning-модели (`glm-5.1`, `glm-5.2`, `kimi-k2.6`, `deepseek-v4-flash`)
возвращают **пустой `content`** и кладут ответ в поле `reasoning`. Но поведение
различается по endpoint:

| Endpoint | `content` | `reasoning` | Кто использует |
|---|---|---|---|
| `/api/chat` (native) | пустой | полный ответ | `prediction_engine._ollama_chat` |
| `/v1/chat/completions` (OpenAI) | пустой | полный ответ | `chatbot` (OpenAI SDK) |

**Решение:** `minimax-m3` — единственная модель, отдающая структурированный JSON в
`content` на обоих endpoint'ах. Поэтому:
- prediction engine: oracle = `minimax-m3`, но analyst/premium остались `glm-5.1`/`glm-5.2`
  (там работает fallback на `reasoning` через native `/api/chat`).
- chatbot: все три роли (`worker`/`analyst`/`premium`) = `minimax-m3` через отдельные
  env-переменные `OLLAMA_CHATBOT_*_MODEL`.

**Риск:** раздвоение конфигурации моделей (prediction engine vs chatbot) — легко
запутаться, какая переменная на что влияет. См. таблицу в §5.

### 3.2 NVIDIA NIM как fallback-провайдер

`prediction_engine.py` теперь поддерживает два провайдера через поле
`RuntimeModelCandidate.provider`. NVIDIA NIM использует OpenAI-совместимый endpoint,
Ollama — native. Fallback-цепочка на роль: `ollama_primary → ollama_fallback → nvidia`.

**Риск:** NVIDIA NIM имеет cold-start latency до 90s для крупных моделей
(`kimi-k3`, `minimax-m3`). Timeout'ы в конфиге (oracle 60s, premium 45s) могут
срабатывать раньше, чем модель прогреется — fallback сработает по timeout, а не по
реальной недоступности.

### 3.3 Command Deck — standalone HTML вне Jinja2

`/command-deck` отдаёт `command_deck.html` напрямую через `HTMLResponse`, минуя
`TEMPLATES.TemplateResponse`. Это осознанно (mobile-first, без `base.html`), но
**ломает единообразие** шаблонов: остальные страницы используют `base.html` с
навигацией и auth-контекстом.

**Риск:** Command Deck не наследует auth-проверку `require_page_auth` (в отличие от
`/predictions`, `/alerts` и др.). Если `WEBUI_AUTH_ENABLED=true`, Command Deck останется
публичным. Сейчас auth выключен (`Local mode`), но это стоит зафиксировать.

### 3.4 Оценка прогнозов — accuracy_score завышен

Формула в `evaluator.py`:
```
score = max(0, 100 - price_error_pct) + 10 (direction) + 10 (in_range), cap 100
```
При малом `price_error_pct` (типично <1% для BTC) score почти всегда упирается в 100.
Наблюдалось: `minimax avg_score=93.3`, `premium avg_score=47.0` — разброс объясняется
не качеством, а тем, что `direction_match` даёт +10, а `in_range` ещё +10. Метрика
**не информативна** для сравнения моделей. Рекомендуется пересмотреть формулу.

### 3.5 Quick tunnel — нестабильный URL

Cloudflare quick tunnel (`cloudflared --url`) генерирует новый случайный
`*.trycloudflare.com` URL при каждом рестарте контейнера. `fix_tunnel.sh` автоматизирует
починку, но URL всё равно меняется. Стабильный URL требует named tunnel + домен
Cloudflare (у владельца нет ни домена, ни аккаунта).

  "SELECT count(*) FILTER (WHERE actual_price IS NOT NULL) FROM forecast_points;"
# Ожидание: > 0

curl -fsS http://localhost:8080/command-deck | head -3
curl -fsS http://localhost:8080/predictions | head -3

## 7. Резюме для ревьюера

**Объём:** 14 коммитов, 14 файлов, +1316 / −241 строк. Основной вес — `webui/app.py`
(+518) и `webui/templates/command_deck.html` (+442, новый файл).

**Характер изменений:** восстановление сломанного runtime (импорты, ключи, оценка
прогнозов) + новый оперативный UI (Command Deck) + починка визуализации прогнозов.

**Главные точки для ревью:**
1. §3.1 — раздвоение конфигурации моделей (prediction engine vs chatbot).
2. §3.3 — Command Deck обходит auth-проверку.
3. §3.4 — `accuracy_score` не информативен.
4. §3.5 — нестабильный tunnel URL (осознанное ограничение).

**Не затронуто:** legacy-зоны (`chatbot/loader.py`, `chatbot/context/*`,
`collector/alerts/detector.py`, `collector/scheduler/briefing.py`), `hypercube/`,
`foresight_*` (отдельный стек). Изменения `.env`/`.env.wored` (ключи, URL) **не
коммитятся** — они в `.gitignore`.
